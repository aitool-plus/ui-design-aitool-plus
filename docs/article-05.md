# 设计师看了沉默，开发者看了流泪：这个AI技能把11家大厂的设计规范吃透了

## 前言

UI设计这件事，说简单也简单，说难也难。简单到画个框填个色就能交差，难到要同时记住11家大厂的圆角、间距、阴影参数，还得保证每个像素都长在规范上。今天聊的这个项目，直接把这件事从"脑力活"变成了"体力活"——不对，连体力活都省了，动动嘴皮子就行。

---

## 一、痛点暴击

做过跨平台项目的团队大概都有过这种经历：

- 周一给iOS做一套界面，周二Android说要适配，周三Web端又冒出个H5需求，周四小程序来敲门，周五老板问能不能顺便出个鸿蒙版……
- 设计师对着Figma手册翻到手抽筋，开发者对着设计稿量像素量到眼发花
- 好不容易对齐了一套风格，产品经理过来说"参考一下Material Design的卡片效果"，然后一切重来

更扎心的是，很多团队根本没有专职UI设计师。全栈开发者被迫营业，画出来的按钮时而像iOS，时而像Windows 95，用户看了直摇头。

这个项目的诞生，本质上就是给这类场景开了一剂猛药。

## 二、能力全景

### 2.1 十一大平台全覆盖

这个项目一口气啃下了11个主流平台的UI设计系统：

| 平台 | 设计体系 | 典型应用场景 |
|:---|:---|:---|
| Apple | iOS Human Interface + macOS | 原生App、桌面应用 |
| Google | Material Design 3 | Android、Web、跨端项目 |
| Microsoft | Fluent Design 2 | Windows应用、办公套件 |
| 微信 | WeUI / 小程序规范 | 微信小程序、公众号H5 |
| 支付宝 | Ant Design Mobile | 金融类小程序、移动端 |
| 字节跳动 | Byte Design / 抖音风格 | 短视频、内容社区 |
| 华为 | HarmonyOS Design | 鸿蒙原生应用 |
| 小米 | MIUI Design | 小米生态应用 |
| OPPO | ColorOS Design | OPPO生态应用 |
| 三星 | One UI | 三星设备适配 |
| 通用Web | Tailwind / Bootstrap | 快速原型、后台系统 |

不是简单贴个皮，是把每个平台的**间距体系、色彩层级、动效曲线、组件尺寸**全部拆解到位。

### 2.2 原厂级1:1还原

什么叫原厂级？举个例子：

- iOS的按钮圆角不是随便写个`border-radius: 8px`，而是区分了`8pt`、`12pt`、`20pt`三种规格，对应不同场景
- Material Design 3的Elevation阴影有5个层级，每个层级的`ambient`、`spot`光源角度和扩散值都不一样
- 微信WeUI的列表单元高度严格控制在`44px`，分割线`0.5px`且带`#E5E5E5`的微妙渐变

这些参数不是拍脑袋编的，是从官方设计令牌（Design Token）里一条条抠出来的。输出的方案拿给设计师看，对方可能会愣一下："这图你从哪扒的？"——不好意思，现生成的。

### 2.3 一键风格切换

同一个界面结构，换一套皮肤就是另一个平台的味道：

```
输入："一个电商商品详情页"
→ 选 iOS 风格 → 大圆角、留白多、底部悬浮操作
→ 选 Material 风格 → 卡片层级、FAB按钮、涟漪反馈
→ 选 微信风格 → 紧凑列表、顶部导航、灰白基调
→ 选 鸿蒙风格 → 自然动效、轻拟物、卡片堆叠
```

结构不变，气质全变。做竞品分析的时候尤其好用——同一套功能，看看不同平台会怎么表达。

## 三、实战场景

### 3.1 零设计基础出图

不会用Figma？不懂色彩理论？没关系。描述清楚要做什么，剩下的交给规范引擎：

- 输入："做一个记账App的添加账单页面，有金额输入、分类选择、日期选择、备注"
- 输出：带完整布局、配色、间距、组件状态的UI方案，直接能用

### 3.2 多风格横向对比

产品立项阶段经常纠结："咱们这个工具类产品，走Apple的极简风还是Google的Material风？"

现在不用纠结了，同一需求输出两套方案并排对比，让数据和审美一起说话。

### 3.3 组件库快速搭建

项目启动时最耗时的往往是搭建基础组件。这个项目能直接输出一套完整的**按钮、输入框、卡片、列表、导航、弹窗、标签页**等基础组件，每个都带多状态（默认、Hover、禁用、加载中、错误态）。

### 3.4 设计稿转代码的桥梁

前端开发者经常吐槽设计师给的稿"没法还原"。这个项目输出的方案本身就基于可落地的设计令牌，从设计到代码的损耗接近于零。

## 四、技术底牌

### 4.1 设计令牌驱动

底层不是写死的样式表，而是基于**Design Token**体系：

- 颜色分层：基础色板 → 功能色板 → 场景色板三级架构
- 间距体系：4px/8px基准网格，所有尺寸都是倍数关系
- 字体阶梯：从`caption`到`headline`预设8级字号，每级对应固定行高
- 圆角规格：小/中/大/全圆角四档，按组件类型自动匹配

### 4.2 响应式内置

输出方案自带断点规则：

| 断点 | 宽度范围 | 布局策略 |
|:---|:---|:---|
| 紧凑 | < 360px | 单列、全宽按钮、底部导航 |
| 手机 | 360px - 768px | 单列+侧边抽屉、标准按钮 |
| 平板 | 768px - 1024px | 双栏、侧边常驻导航 |
| 桌面 | > 1024px | 多栏、顶部导航、浮动面板 |

### 4.3 状态全覆盖

每个组件都考虑了完整交互状态：

- 默认态 → Hover态 → 按下态 → 禁用态
- 加载中 → 空数据 → 错误态 → 成功反馈
- 深色模式自动适配

## 五、上手姿势

### 5.1 一句话生成

最轻量的用法，描述需求即可：

```
"生成一个iOS风格的设置页面，包含账号管理、通知设置、隐私权限、关于我们四个模块"
```

### 5.2 带约束生成

需要更精细的控制，可以追加参数：

```
"生成一个Material Design风格的登录页面，要求：
- 主色调使用品牌蓝 #1890ff
- 支持手机号+验证码登录
- 底部要有第三方登录入口
- 适配深色模式"
```

### 5.3 批量对比生成

做方案比选的时候，一次输出多平台版本：

```
"同一个社交App的个人主页，分别生成iOS、Material、微信三种风格的方案"
```

## 七、写在最后

UI设计这件事，本质上是在**约束中创造**。每个平台的设计规范看似是枷锁，实则是经过亿级用户验证的最优解。这个项目厉害的地方，不是替代设计师，而是把"记住规范"这件苦力活接管了，让人把精力放在真正的创意上。

当然，机器生成的方案再工整，也替代不了人对业务场景的理解。最好的用法是：把它当做一个**超级助手**——快速出方案、快速验证、快速迭代。最终的决策权，还是在人手里。
